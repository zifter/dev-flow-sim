# dev-flow-sim

Симулятор потока задач через процесс разработки. Задаёте workflow как в Jira: этапы, роли, сколько часов занимает задача на каждом этапе. Модель прогоняет поток задач через команду из людей (сценарий A) и через ту же команду, где часть этапов делают ИИ-агенты (сценарий B). На выходе: пропускная способность, сроки, загрузка ролей и где копится очередь.

Главный вопрос, на который отвечает модель: если разработка станет в 10 раз быстрее, во что упрётся система.

## Запуск

Откройте `index.html` в браузере. Сборка и зависимости не нужны.

Тесты модели:

```bash
node --test test/
```

## Что задаётся

- **Поток задач.** Пуассоновский поток N задач в неделю или бэклог, выданный разом. Для сценария B поток можно умножить.
- **Роли.** Пулы людей: разработчики, ревьюеры, QA и т. д. Одна роль может обслуживать несколько этапов.
- **Этапы.** Кто делает, время на задачу (минимум, типичное, максимум — треугольное распределение), возврат на более ранний этап с вероятностью.
- **Агент на этапе (только B).** Во сколько раз быстрее, сколько агентов параллельно, сколько часов человек тратит на постановку и проверку и из какой роли этот человек. Отдельная вероятность возврата, если этап делал агент.
- **Календарь.** Люди работают по рабочему графику, агенты могут работать 24/7.

## Что считается

- Выполнено задач в неделю и предел системы (аналитически: доступное время роли / нагрузка на задачу, минимум по ролям).
- Срок задачи: медиана и 85-й перцентиль, в календарных днях.
- Средний WIP, эффективность потока, возвраты на задачу.
- Загрузка каждой роли, очередь и ожидание на каждом этапе.
- Доска с движением задач во времени и график задач по этапам (WIP или накопительный CFD).

## Как устроено

- `sim.js` — ядро: дискретно-событийная симуляция и аналитическая оценка нагрузки. Работает в браузере и в node.
- `example.js` — пример конфигурации. Цифры условные.
- `index.html` — интерфейс.
- Конфиг хранится в `localStorage` браузера, его можно выгрузить и загрузить как JSON.

Ограничения модели: очереди FIFO с приоритетом поздних этапов, нет WIP-лимитов, нет переключения контекста и блокировок между задачами.
